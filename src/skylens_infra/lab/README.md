# skylens_lab — KOREN 사용 정당성 실측

중간보고서는 "촬영 영상은 KOREN 연구망을 경유하여 Core HPC로 전송된다"고 적었다.
심사에서 받을 질문은 하나다. **그래서 KOREN이 아니면 안 되는 이유가 무엇인가.**

이 디렉터리는 그 질문에 **측정으로** 답하기 위한 것이다. 주장을 먼저 세우고 숫자를
맞추는 게 아니라, 재고 나온 숫자로 주장을 세운다. 무너지는 주장은 버린다.

---

## 0. 측정 지점

| 지점 | 정체 | 망 | 접속 |
|---|---|---|---|
| `pi-175` | 라즈베리파이 5, Debian 13 | **상용 가정 회선**, KOREN 등록 IP(175.126.98.44) | VPN 경유 SSH, 키 |
| `mnd-koren` | 대전 VM, Ubuntu 24.04, 4코어 15GB | **KOREN 내부**(116.89.187.181) | SSH 26022, 키 |
| `pangyo` | 판교 HPC VM, V100 16GB | **KOREN 내부**(10.246.246.9) | SOCKS 프록시 경유, 포털 계정 필요 |

`pi-175`와 `mnd-koren`은 **같은 건물·같은 지역이 아니라 서로 다른 망**이다. 이 둘이
같은 원격 파일을 같은 시각에 받으면, 차이는 회선의 차이다. 이것이 이 실험의 뼈대다.

## 1. 검증할 주장과 측정 설계

| # | 주장 | 측정 | 상태 |
|---|---|---|---|
| C1 | KOREN은 국내 구간에서 상용 회선보다 빠르다 | 두 노드가 같은 국내 미러에서 같은 50MB 구간을 Range로 받는다 | **측정 중** |
| C2 | 그 차이는 시간대와 무관하게 유지된다 | 10분 주기로 며칠 수집해 p95와 변동계수를 본다 | **수집 중** |
| C3 | `.spz` 버스트가 끝나는 시간이 KOREN에서 더 짧다 | 4MB·30MB 전송 완료 시간. 지휘관이 새 3D를 보기까지의 시간 | 상용 경로 측정 중, KOREN 내부 대기 |
| C4 | 대전↔판교(KOREN 내부)는 상용 경로로 대체할 수 없다 | 같은 payload를 두 경로로 왕복시켜 비교 | **차단됨**(§4) |
| C5 | 작은 전송은 대역이 아니라 지연과 TCP 시작 구간이 지배한다 | 4MB·30MB·100MB를 단일/4스트림으로 비교 | **측정 중** |
| C6 | KOREN의 이점은 국내에 한정된다 | 해외 목적지(OVH 프랑스)로도 같은 측정 | **측정 중** |
| C7 | 인제스트 구간은 KOREN이 못 고친다 | 5G 상행 실측과 비교 | 미착수 |
| C8 | 지연의 흔들림이 작다 | TCP 핸드셰이크 왕복시간의 지터와 p95 | **수집 중** |

C6과 C7은 **우리 주장을 약화시키는 쪽**이다. 그래도 넣는다. 심사에서 먼저 지적당하는
것보다 우리가 먼저 재서 범위를 좁히는 쪽이 낫다.

## 2. 첫 측정 결과 (2026-10-05)

### 같은 파일, 같은 시각, 두 회선

| 목적지 | 대전 (KOREN) | 파이 (상용) | 배수 |
|---|---:|---:|---:|
| 국내 · 카카오 미러 | **2,034 Mbps** | 438 Mbps | 4.6배 |
| 국내 · 네이버 미러 | **1,198 Mbps** | 442 Mbps | 2.7배 |
| 해외 · OVH 프랑스 | 42.8 Mbps | **72.2 Mbps** | 0.6배 |

국내에서는 KOREN이 압도하고, 해외에서는 상용망이 낫다. C1과 C6이 동시에 지지된다.
우리 시스템의 모든 구간이 국내이므로 이 비교는 그대로 쓸 수 있다.

### 전송 크기에 따른 처리량 (파이 ↔ 대전, SSH 위)

| 크기 | 방향 | 스트림 | 완료 시간 | 처리량 |
|---|---|---|---:|---:|
| 4 MB | 올림 | 1 | 0.63 s | 50.7 Mbps |
| 4 MB | 내림 | 1 | 0.50 s | 63.5 Mbps |
| 30 MB | 올림 | 1 | 1.32 s | 181.4 Mbps |
| 30 MB | 내림 | 1 | 0.95 s | 252.8 Mbps |
| 100 MB | 올림 | 4 | 2.74 s | 291.6 Mbps |
| 100 MB | 내림 | 4 | 2.42 s | 331.2 Mbps |

같은 회선인데 4MB에서 50 Mbps, 30MB에서 181 Mbps가 나온다. **작은 전송은 회선이 아니라
TCP 시작 구간이 지배한다**는 C5의 직접 증거다. CPU 점유율이 12% 이하라 암호화 한계도 아니다.

이 사실은 설계에 바로 영향을 준다. `.spz`를 4MB로 줄여도 전송 시간이 비례해 줄지 않는다.
줄여야 할 것은 바이트가 아니라 **왕복 횟수**다.

### 왕복시간

| 구간 | 중앙값 | 지터 |
|---|---:|---:|
| 파이 → 대전 | 8.1 ms | 0.9 ms |
| 대전 → 국내 앵커 | 4.4 ms | 0.6 ms |
| 대전 → 해외 앵커 | 32.4 ms | 2.6 ms |

## 3. 부수적으로 확인된 사실

**대전은 등록 IP에서도 26022 외 모든 포트가 막혀 있다.** 10000~15000 범위에 리스너를
띄우고 등록 IP인 파이에서 접속을 시도했으나 전부 타임아웃이었다. 배치 문서가 전제한
"대전 10889/TCP·10890/UDP 인바운드"는 **현재 열려 있지 않다.** SSH 터널 방식이
우회가 아니라 유일한 길이었음이 확인된다.

**대전에서 175로는 80·443만 열린다.** 따라서 설계상의 "대전이 175에서 SRT를 당긴다"는
경로도 아직 성립하지 않는다. 10890/UDP 포트포워딩이 필요하다.

## 4. 막힌 것 — 사람이 한 번씩 해 줘야 하는 일

### (a) 판교 측정 (C4의 전제)

판교는 SOCKS 프록시를 거쳐야 하고, 그 프록시가 포털 계정을 요구한다. 무인 측정에는
자격증명이 저장돼 있어야 한다.

```bash
# 대전에서 한 번
printf 'ID=포털아이디\nPW=포털비밀번호\n' > ~/.koren_portal && chmod 600 ~/.koren_portal
```

그리고 판교에 대전의 공개키를 넣는다. 대전의 키는 `~/.ssh/id_ed25519.pub`에 있다.

```bash
# 판교에 들어가서 한 번
echo '<대전 공개키 한 줄>' >> ~/.ssh/authorized_keys
```

둘이 끝나면 `~/lab/koren_link.sh`가 무인으로 돈다.

### (b) 직결 경로 신청 (C4를 제대로 재기 위해)

지금 대전↔판교는 **SOCKS 프록시를 경유**한다. 그래서 측정값은 KOREN 백본의 상한이
아니라 프록시의 성능이다. 백본 자체를 재려면 두 VM 사이 직결 포트가 열려야 한다.
KOREN 정책상 10000~15000 범위를 신청할 수 있다.

### (c) 5G 상행 실측 (C7)

현장 게이트웨이 구간은 아직 추정값이다. 휴대폰 테더링으로 같은 프로브를 돌리면
인제스트 상한을 실측으로 바꿀 수 있다.

## 5. 구성

```
lab/
├─ probe.py        측정 본체. RTT · 버스트 · 병렬 · CPU · 공개 기준선
├─ run_pi.sh       파이에서 10분마다 (cron)
├─ run_mnd.sh      대전에서 10분마다 (cron)
├─ koren_link.sh   대전↔판교. 자격증명이 들어오면 동작
├─ aggregate.py    JSONL 집계. 평균이 아니라 p95 와 변동계수를 본다
└─ (결과는 각 노드 ~/lab/results, 파이 것은 매시 대전으로 모임)
```

```bash
# 집계 보기
ssh mnd 'cd ~/lab && python3 aggregate.py results/*.jsonl'
ssh mnd 'cd ~/lab && python3 aggregate.py --md --since 2026-10-06 results/*.jsonl'
```

## 6. 원칙

- 평균을 쓰지 않는다. 중앙값·p95·변동계수를 본다. 재난 대응에서 중요한 것은 나쁜 쪽 꼬리다.
- 한 번 잰 값을 결론으로 쓰지 않는다. 시간대를 가로질러 며칠 모은 뒤에 말한다.
- 우리에게 불리한 측정도 같이 싣는다. C6·C7이 그것이다.
- 측정하지 않은 것은 "미측정"이라고 적는다. 추정값과 실측값을 섞지 않는다.
