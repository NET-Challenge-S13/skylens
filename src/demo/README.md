# demo — 데모 런처

각 컴포넌트를 **실제 코드 그대로** 조립해 한 대의 머신에서 돌린다. 이 디렉터리에는 어떤 컴포넌트의 동작도 다시 구현하지 않는다. 런처가 하는 일은 의존 순서대로 띄우고, 데모 설정을 주입하고, 로그를 읽을 수 있게 묶는 것뿐이다.

```bash
npm run demo
```

## 데모에서 바뀌는 것

| 실제 | 데모 |
|---|---|
| 드론이 현장에서 촬영 | `res/static/video/h265`의 사전 인코딩 HEVC 영상 |
| Core HPC의 3DGS 학습 | `res/static/demo/segments.json`의 구간×수준 자산 |

그 외에는 전부 실제 경로다 — 드론이 게이트웨이에 붙고, 프록시가 코어로 중계하고, 코어가 모델 API에 잡을 발행하고, 현황판이 릴레이를 통해 받는다.

## 기동 순서

의존 순서대로 띄우고 **각 단계를 헬스체크로 게이팅**한다. 상류 없이 먼저 뜬 컴포넌트는 첫 몇 초를 재시도로 보내며 버그처럼 보이는 실패 로그를 쏟아내기 때문이다.

```
model(8100) → core(8080) → proxy(8082) → gateway(8081) → client(8090) → vite(5173) → drone
```

드론이 마지막이고, **대기 상태로 시작한다**. 시나리오는 관제탑에서 경로를 배정해야 시작된다.

## 시나리오 (COMPONENTS.md §5.2)

| 단계 | 화면 |
|---|---|
| 1 | 정지 상태 — `대기 중 — 관제탑에서 경로를 지정하십시오` |
| 2 | 경로 배정 → `태스크 지정 완료` |
| 3 | `드론이 현장에 도착해 연결되면 작업이 시작됩니다` (약 10초) |
| 4 | `드론 연결됨 — 임무 수행 중`, 경로 왕복 비행 시작 |
| 5 | 드론이 구간을 지날 때마다 현황판이 딜레이 패턴으로 갱신 |

3단계의 대기가 성립하려면 드론이 **도착 시점에 hello를 보내야** 한다. 런처가 `SKYLENS_DRONE_HELLO_ON_ARRIVAL=1`을 주는 이유다. 이동 중 텔레메트리는 계속 흐르지만(관제탑이 이동 경로를 그릴 수 있도록), 코어는 hello를 받은 드론만 "도착"으로 센다.

## 접속 주소

| 화면 | 주소 |
|---|---|
| 관제탑 | http://localhost:8080/res/static/control.html |
| 현황판 | http://localhost:8090/res/static/status.html |
| 드론 패널 | http://localhost:5173/src/skylens_drone/index.html |

관제탑은 코어가, 현황판은 클라이언트 서버가 서빙한다(둘 다 개발 모드에서는 Vite로 리버스 프록시). 드론 패널은 데모 확인용이며 실제 배치에서는 Tauri 앱이다.

## 점 레이어 (점 + 고도색)

현황판 **메인 화면은 그대로 두고**, 좌하단에 작게 뜨는 참고용 패널이다(별도 씬과 카메라로 그리므로 메인 화면의 카메라·추적·마커는 영향을 받지 않는다). 점 구간이 들어오기 시작하면 패널이 나타나고, 아래의 **점 · 고도색** 버튼으로 닫거나 연다. 복원 파이프라인 04d가 구간마다 내는 초벌(수준 1, 그 구간의 새 영역만)과 정밀본(수준 2, 구간 전체)을 `point-chunk`로 받아, 정밀본이 오면 같은 구간의 초벌을 **교체**한다. 노드에서 코어로 보내는 전송은 아직 정해지지 않았으므로, 데모에서는 코어가 미리 준비한 파일을 같은 순서로 재생한다.

```bash
npm run demo:points          # 촬영본을 res/static/demo/points/로 복사하고 points.json 생성 (한 번, 약 110MB, 커밋하지 않음)
npm run demo                 # 미션이 active가 되면 코어가 4초 간격으로 재생
```

- 기본 원본 경로는 `src/demo/preparePoints.ts`의 `DEFAULT_SRC`이고, `--src <dir>`로 바꿀 수 있다. 원본은 읽기만 한다.
- 재생 순서: 틱 k에 구간 k 초벌, 이어서 구간 k-1 정밀본. 새 구간의 첫 수준은 기다리지 않는다.
- 환경변수(코어): `SKYLENS_DEMO_POINTS_INTERVAL_MS`(기본 4000), `SKYLENS_DEMO_POINTS_AUTOSTART=1`(미션 없이 첫 뷰어가 붙으면 재생), `SKYLENS_DEMO_POINTS_MANIFEST`, `SKYLENS_DEMO_POINTS_URL_BASE`.
- `points.json`이 없으면 코어는 `point feed off` 한 줄만 남기고 나머지는 그대로 동작한다.
- 패널이 닫혀 있으면 도착만 기록하고 파일은 받지 않는다. 여는 순간 구간마다 가장 높은 수준만 받는다. `?points=off`는 닫힌 채로 시작한다.
- 패널 카메라는 도착한 점 전체를 비추고, 구간이 늘면 따라 넓어진다. 패널 안을 끌면 그때부터는 조작자가 카메라를 가지며, 더블클릭하면 다시 전체 보기로 돌아간다.
- 범례는 화면에 올라온 점의 하위 1% 높이를 0 m로 둔 상대 높이다.
- 한 프레임에 그리는 점은 최대 300만 개다. 넘으면 모든 구간을 같은 비율로 균일하게 솎아 그린다(점은 메모리에 그대로 있다).
- `?points=rgb`는 고도색 대신 촬영 RGB로 칠한다(비교용).

실측(실제 GPU에서 재는 스크립트): `node src/test/client/pointBoardProbe.mjs`. 사용법은 파일 머리 주석에 있다.

## 무인 확인

사람이 클릭하지 않고 시나리오를 끝까지 돌리려면:

```bash
npm run demo                                        # 한 셸
node --import tsx src/test/demo/driveScenario.ts    # 다른 셸
```

관제탑이 보내는 `assign-route` 한 건을 대신 보내고, 이후 미션 단계와 딜레이 패턴 도착을 그대로 출력한다. 겹침(앞 구간이 정제되는 동안 다음 구간의 수준 1 도착)이 관측되지 않으면 실패로 끝난다.

## 종료

`Ctrl+C` 로 전체가 함께 내려간다. 컴포넌트 하나가 죽으면 런처가 나머지도 정리한다 — 한쪽이 사라진 파이프라인을 멀쩡한 것처럼 두면 진단이 더 어려워지기 때문이다.
