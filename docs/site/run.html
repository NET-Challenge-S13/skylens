직접 돌려보기

화면만 보고 싶으면 앱을 받아서 열면 되고, 파이프라인 전체를 내 컴퓨터에서 돌리고 싶으면 데모 런처를 쓰면 돼요. 데모도 드론 영상부터 코어 · 모델 서버 · 두 화면까지 전부 실제 코드로 돌아가요.

앱으로 받기

두 화면은 Windows · macOS · Linux 데스크톱 앱으로 나와 있고, 현황판은 Android 앱도 있어요. 최신 릴리스에서 받아요.

릴리스 파일
운영체제 현황판 관제탑
Windows (x86_64) skylens-client-windows-x86_64.exe skylens-control-windows-x86_64.exe
macOS (Apple Silicon) SkyLens-macos-arm64.dmg 하나에 두 앱이 다 들어 있어요
Linux (x86_64) skylens-client-linux-x86_64 skylens-control-linux-x86_64
Android skylens-board-android.apk 없음

현황판 앱은 실행하면 먼저 배치된 브리지 서버에 붙고, 거기가 응답하지 않으면 이 컴퓨터에서 도는 데모(127.0.0.1:8080)에 붙어요. 관제탑 앱은 이 컴퓨터의 코어에 붙어요. 다른 곳에 붙이려면 --core로 주소를 줘요. 

skylens-client --core 192.168.0.10:8080
skylens-control --core ws://192.168.0.10:8080/control

서명은 없어요. macOS에서는 처음 열 때 오른쪽 클릭 후 열기를 누르거나 xattr -dr com.apple.quarantine <앱>을 실행해 주세요. Android 앱은 실제 기기에서는 아직 확인하지 않았어요.

데모 직접 돌리기

Rust 1.99 이상, Go, MediaMTX, ffmpeg가 필요해요. 모델 서버의 UNet 추론에 쓰는 libtorch는 빌드할 때 알아서 받아요. 촬영 영상도 처음 실행할 때 릴리스에서 받아요. 

(cd src/skylens_core && go build -o ../../target/skylens-core .)
cargo run --release -p skylens-demo -- --native

--native를 붙이면 관제탑과 현황판 앱 창이 함께 떠요. 빼면 브라우저로 봐요.

브라우저 주소
화면 주소
관제탑 http://localhost:8080/ (코어가 보내 줘요)
현황판 http://localhost:8090/ (게이트웨이 역할을 하는 런처 내장 서버)

끌 때는 Ctrl+C 한 번이면 돼요. 런처가 띄운 것을 역순으로 내려요. 어느 하나가 죽으면 나머지도 같이 정리해요. 반쯤 죽은 파이프라인을 멀쩡한 것처럼 두면 진단이 더 어렵기 때문이에요.

데모는 이렇게 흘러가요

  1. 시작하면 경로를 기다려요

    관제탑의 미션 단계가 "대기"예요. 촬영한 비행 경로가 경로 계획에 미리 들어가 있어요.

  2. 관제탑에서 경로를 배정해요

    경로 계획 · ROUTE에서 Assign을 누르면 "태스크 지정"으로 바뀌어요. 배정이 새 미션의 시작이라, 지난 미션의 결과는 여기서 지워져요. --auto를 붙이면 런처가 3초 뒤에 대신 눌러요.

  3. 드론이 붙고 영상이 들어와요

    드론 세 대가 도착 인사(drone_hello)를 보내면 "임무 수행"이 되고, 관제탑 오른쪽 아래에 카메라 영상이 떠요. 현황판은 이때부터 "3D 공간 생성 중" 대기 시간을 재요.

  4. 지나간 구역부터 현황판이 채워져요

    구역마다 거친 미리보기가 먼저 뜨고, 이어서 정제된 점과 메시로 바뀌어요. 왼쪽 위 서버 패널의 진행 단계 격자에서 구역마다 어디까지 왔는지 볼 수 있어요. 사람이나 위험구역이 잡히면 카메라가 그 지점으로 다가가요.

데모에서 바뀌는 건 기체 쪽뿐이에요

컴포넌트는 전부 실제 코드예요. 한 대의 컴퓨터에서 재현할 수 없는 것만 바꿔 놨어요.

실운영과 데모의 차이
항목 실운영 데모
촬영 기체 카메라 → SRT 실제 촬영본(드론 세 방향, 첫 비행 약 53초)을 SRT로 송출
비행 DJI Fly 웨이포인트 비행 촬영본에 기록된 GPS · 고도 · 방위를 영상과 맞춰 재생
경로 계획 운용자가 지도에서 지정 촬영 경로가 미리 들어가 있고, 운용자는 배정만 눌러요
게이트웨이 · 프록시 브리지와 대전의 nginx 런처 안의 현황판 서버가 대신해요

복원 · 탐지 · 메시 · 배포는 데모에서도 실제 경로예요. 영상이 코어에서 프레임으로 뽑히고, 모델 서버가 점 · 메시 · 탐지를 만들어 코어로 돌려주고, 코어가 두 화면에 나눠 보내요. 모델 서버가 없으면 화면은 그 자리를 비워 두고 없다고 표시해요.

자주 쓰는 옵션

데모 런처 (skylens-demo)
옵션 하는 일
--native관제탑 · 현황판 앱 창도 같이 띄워요
--auto미리 계획된 경로를 런처가 배정해서 사람 없이 끝까지 돌아요
--no-loop촬영본을 한 번만 보내요. 끝나면 드론은 마지막 위치에 머물러요
--publish-delay S영상과 드론을 S초 늦게 시작해요. 화면을 다 띄운 뒤 시작하고 싶을 때 써요
--full-footage낮게 난 두 번째 비행까지 보내요
--no-model모델 서버 없이 화면만 띄워요
--model-addr H:P이미 떠 있는 모델 서버(예: GPU 서버로 가는 터널)를 써요
--online내 컴퓨터가 아니라 KOREN 위에 배치된 서버에 붙어서 돌아요 (VPN 필요)
관제탑 앱 (skylens-control)
옵션 하는 일
--core URL붙을 코어. 기본은 ws://127.0.0.1:8080/control
--display points|black|aerial건물 표시 방식(점 · 검정 텍스처 · 실사 항공뷰)
--video off카메라 영상 패널을 꺼요. 영상은 ffmpeg로 받아요

VWorld 키 설정

관제탑의 위성 영상과 건물 데이터는 VWorld 인증 키가 필요해요. 코어가 키를 읽어서 VWorld에 대신 요청하기 때문에 키는 화면 쪽으로 나가지 않아요.

코어는 VWORLD_KEY 환경변수를 먼저 보고, 없으면 SKYLENS_VWORLD_ENV가 가리키는 파일, 그것도 없으면 저장소 부모 폴더의 .env.vworld를 읽어요. 

# 저장소 바로 바깥 디렉터리에서
cat > .env.vworld << EOF
VWORLD_KEY=<vworld.kr에서 발급한 인증키>
EOF

키가 없어도 괜찮아요. 지형과 건물만 안 그려지고 나머지는 그대로 돌아가요.

Rust · Go
명령 하는 일
cargo build --workspace공통 계약 · 드론 · 모델 서버 · 두 화면 · 데모를 빌드해요
cargo test --workspace테스트를 돌려요
cargo clippy --workspace --all-targets린트를 돌려요
go build ./... · go test ./...src/skylens_core에서 코어를 빌드하고 테스트해요
Python: UNet 학습 코드, 의존성은 uv로 관리해요
명령 하는 일
uv sync.venv/를 만들고 패키지를 설치해요
uv run pytest테스트를 돌려요
uv run ruff check src/린트를 돌려요
uv run jupyter lab학습 노트북(train.ipynb)을 열어요

torch는 PyPI에서 안 받아요. CUDA 12.8 인덱스에서 받도록 pyproject.toml에 지정해 뒀어요. Python은 3.11 이상 3.14 미만이고, 기준 버전은 3.13이에요.

두 대로 나눠서 보고 싶다면

관제탑과 현황판은 각자 다른 컴퓨터에서 전체화면으로 띄우는 걸 전제로 만들었어요. 데모를 돌리는 컴퓨터의 IP가 192.168.0.10이라면, 같은 네트워크의 다른 컴퓨터에서 브라우저로 http://192.168.0.10:8080/(관제탑)이나 http://192.168.0.10:8090/(현황판)을 열거나, 앱에 --core로 그 주소를 주면 돼요.
