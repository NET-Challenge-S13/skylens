# 공개 베이스라인 정리 (SkyLens 비교용)

> 이 문서는 보고서에 공개 수치를 인용할 때 쓰는 조사 자료다. 우리 수치와 나란히 놓되, 어떤 표도 같은 지표가 아니라는 점을 표마다 적었다.
> 중간보고서(260817) 표 12 의 참고 열에 적힌 LLVIP 0.965 는 2차 출처에서 퍼진 값이고, 원문(Jia et al., ICCVW 2021 표 3)은 thermal-only 0.946 이다. 다음 보고서에서 고쳐야 한다.


조사일 2026-09-20. 웹 검색 + 원문 PDF 확인. 각 수치마다 **1차 출처에서 직접 확인했는지** 표시한다.
확인 표기: `[P]` = 논문 PDF 본문 표에서 직접 읽음, `[S]` = 2차 출처(초록·검색 요약·인용 논문)만 확인, `[?]` = 확인 실패.

우리 수치(재계산하지 않음, 프로토콜: pooled/per-source, match radius max(8px, 0.15*h), mAP는 score >= 0.05 검출 기준, F1은 threshold 0.3, top-k 300):

| 항목 | v4 (전 데이터셋 학습) | 최신 combo (stride-2 head + rounded gaussian radius) |
|---|---|---|
| LLVIP mAP@50 | 0.8522 | 0.8576 |
| VisDrone-548 tiled mAP@50 | 0.5104 | 0.6711 |
| SARD-394 tiled mAP@50 | 0.7199 | 0.8202 |
| SARD F1@0.3 | 0.7946 | 기록 없음 |
| hazard seg (512 eval) | mIoU 0.6256 / collapse 0.728 / fire 0.503 / road_blocked 0.343 | 동일 |
| SARD 미학습 모델(zero-shot) | SARD mAP@50 0.4110, best-threshold F1 0.580 | 해당 없음 |

> 전제: 우리 person 헤드는 **점(CenterNet-style) 검출**이고, 평가도 **거리 반경 매칭**이다. 아래 공개 수치는 전부 **박스 IoU 기반 mAP**다. 따라서 어떤 표도 "같은 지표"가 아니다. 이 점은 표마다 반복해서 적는다.

## 1. SARD (가장 중요)

원 논문: Sambolek & Ivasic-Kos, IEEE Access 2021.

| 모델 | 지표 | 수치 | 학습 데이터 | 해상도 | 확인 | 우리와 비교 가능한가 |
|---|---|---|---|---|---|---|
| YOLOv4 (SARD 학습) | mAP (IoU 기준 명시 불확실, confidence threshold 0.4) | **97.15%** | SARD 단독 | 832x832가 최고 | [S] 초록·다수 2차 출처 | 불가. 아래 주의 참조 |
| YOLOv4 (SARD 학습) | AP, precision/recall | AP 약 96%, recall > 91%일 때 precision 96% | SARD 단독 | 미상 | [S] | 불가 |
| Faster R-CNN / RetinaNet / Cascade R-CNN | AP | YOLOv4보다 낮음 (정확한 값 미확인) | SARD 단독 | 미상 | [?] | 표 수치 확보 실패 |

후속 연구(같은 저자 계열):

| 모델 | 지표 | 수치 | split | 확인 |
|---|---|---|---|---|
| YOLOv8n (SARD fine-tune) | P 93% / R 78% / mAP@0.5 **86.8%** / mAP@0.5:0.95 54.9% | 학습 817장(2,017 person), 검증 792장(2,611 person) | [P] scitepress 전문 | |
| YOLOv8x (SARD fine-tune) | P 95% / R 83% / mAP@0.5 **91.3%** / mAP@0.5:0.95 63.8% | 위와 동일 | [P] | |

(위 YOLOv8 수치는 Sambolek & Ivasic-Kos, ICPRAM 2024, SciTePress 논문 본문에서 직접 확인.)

**비교 불가 사유 (중요)**
- IEEE Access 2021 논문 PDF 본문을 끝내 받지 못했다(IEEE/ResearchGate/Academia 모두 403). 97.15%는 초록과 여러 2차 출처에서 일관되게 나오지만, **IoU 임계값 정의와 test split 구성(몇 장인지)** 은 1차 확인 못 했다. 보고서에 쓸 때는 "저자 보고, IoU 정의 미확인"이라고 적어야 한다.
- split이 다르다. 우리는 SARD-394 자체 split, 공개 수치는 저자 split(2021)·817/792(2024).
- 우리는 **tiled 추론 + 점 매칭**, 저자들은 전체 프레임 박스 mAP.
- 저자 모델은 SARD 단독 특화 모델, 우리 모델은 5개 소스 joint 모델이다.
- 따라서 "우리 0.8202 vs 저자 0.9715"를 성능 열세로 읽으면 안 된다. 같은 축이 아니다.

**우리 쪽에서 정당하게 말할 수 있는 것**: SARD를 학습에서 뺀 모델이 0.4110 → 넣으면 0.8202. 이 delta는 우리 split 안에서 자체적으로 유효하고, 공개 수치와 무관하게 주장할 수 있다.

## 2. VisDrone2019-DET

원 논문(챌린지 리포트) PDF 본문에서 직접 확인 `[P]`.

- 데이터: 8,599장, 10 클래스, 540k+ 박스. split = train 6,471 / val 548 / test 1,580 (챌린지 리포트 표기; Ultralytics 등 일부 문서는 test-dev 1,610으로 적는다).
- 지표: COCO 프로토콜. AP = IoU 0.50:0.95 평균(전 클래스), AP50 = IoU 0.5.
- **사람 정의**: 서 있거나 걷는 사람 = pedestrian, 그 외 자세 = person.

전체 (test set, 10 클래스 전부) `[P]`:

| 방법 | AP | AP50 | AP75 |
|---|---|---|---|
| DPNet-ensemble (2019 우승, Cascade R-CNN 기반) | 29.62 | **54.00** | 28.70 |
| RRNet (CenterNet 기반) | 29.13 | 55.82 | 27.23 |
| ACM-OD (FPN) | 29.13 | 54.07 | 27.38 |
| CornerNet (주최측 베이스라인 중 최고) | - | - | - (표 2 기준 하위권) |
| RetinaNet (주최측 베이스라인, 최저) | - | - | - |

클래스별 AP(=AP@0.50:0.95, **AP50 아님**) `[P]`:

| 방법 | pedestrian | person |
|---|---|---|
| DPNet-ensemble | **32.31** | 15.97 |
| RRNet | 30.44 | 14.85 |
| ACM-OD | 30.75 | 15.50 |
| CenterNet (A.6) | 27.99 | 11.61 |
| FPN (베이스라인) | 15.69 | 5.02 |
| RetinaNet (베이스라인) | 9.91 | 2.92 |

나중 detector (2차 출처 `[S]`, test set): PT-DETR AP50 38.4 / AP 28.1, RT-DETR-R18 36.8 / 26.4, YOLOv8-M 34.6 / 24.6. 이 숫자들은 챌린지 리포트 AP50(54.00)보다 낮은데, split·학습 설정·앙상블 여부가 달라서 그대로 줄세우면 안 된다.

**우리 0.6711 (VisDrone-548 tiled mAP@50)이 공개 54.00을 이긴다고 말할 수 없는 이유**
- 우리는 **val 548장**, 공개 표는 **test 1,580장**.
- 우리는 **person 계열 클래스만**, 공개 AP50은 **10 클래스 평균**(car 같은 쉬운 클래스가 포함되어 평균을 올린다).
- 우리는 tiled 추론, 점 매칭 반경 기반. 공개는 전체 프레임 박스 IoU.
- 클래스별 수치는 AP50이 아니라 AP@[.5:.95]라서 우리 mAP@50과 직접 대응하지 않는다.

## 3. LLVIP (Jia et al., ICCVW 2021)

원 논문 PDF 표 3에서 직접 확인 `[P]`.

- 데이터: 30,976장 = 15,488쌍. 가시광 원본 1920x1080, 적외 1280x720. 저자 실험은 **70% train / 30% test**(GitHub 배포본은 train/test 접두어로 분리).
- 지표: mAP50 = IoU 0.5, mAP = 0.5:0.95. 클래스는 pedestrian 1개.

| 모델 | 모달리티 | mAP50 | mAP75 | mAP | 확인 |
|---|---|---|---|---|---|
| YOLOv5l | visible(RGB only) | **0.908** | 0.519 | 0.500 | [P] |
| YOLOv5l | infrared(thermal only) | **0.946** | 0.722 | 0.619 | [P] |
| YOLOv3 | visible | 0.859 | 0.379 | 0.433 | [P] |
| YOLOv3 | infrared | 0.897 | 0.534 | 0.528 | [P] |

원 논문에는 **융합(RGB+T) 검출 결과가 없다.** 융합 수치는 후속 CFT 논문(Qingyun et al.) 표 1·4에서 확인 `[P]`:

| 모델 | 모달리티 | mAP50 | mAP75 | mAP |
|---|---|---|---|---|
| Faster R-CNN (ResNet50) | RGB | 91.4 | 48.0 | 49.2 |
| Faster R-CNN (ResNet50) | Thermal | 96.1 | 68.5 | 61.1 |
| SSD (VGG16) | RGB / Thermal | 82.6 / 90.2 | 31.8 / 57.9 | 39.8 / 53.5 |
| Two-stream YOLOv5 baseline | RGB+T | 95.8 | 71.4 | 62.3 |
| CFT | RGB+T | **97.5** | 72.9 | 63.6 |

주의: 검색 요약 일부가 적외 YOLOv5 mAP50을 0.965로 적는데, **원문은 0.946**이다. 0.965는 잘못된 전파로 보인다.

**우리 0.8576과의 비교 불가 사유**
- 우리는 점 검출 + 반경 매칭, 위는 전부 박스 IoU 0.5.
- 우리는 LLVIP 단독 특화가 아니라 5개 소스 joint 학습, 입력도 4채널 고정 파이프라인.
- split 구성이 우리 평가 split과 동일하다는 보장이 없다.
- 그래도 LLVIP는 **우리가 공개 수치와 가장 가까운(0.86 vs 0.91 RGB-only / 0.95 thermal-only) 항목**이라, "동일 지표가 아님"을 명시한 채 '같은 자릿수'라는 정도로만 언급하는 게 안전하다.

## 4. RescueNet (Rahnemoonfar, Chowdhury & Murphy, Scientific Data 2023)

- 데이터: 4,494장, 3000x4000, 허리케인 Michael UAV. split = train 3,595 / val 449 / test 450 `[P, PMC 본문]`.
- 클래스 10개: Water, Building-No-Damage, Building-Minor, Building-Major, Building-Total-Destruction, Vehicle, Road-Clear, **Road-Blocked**, Tree, Pool. **per-class IoU는 보고된다.**

논문 벤치마크 표 `[P, PMC 본문]` (IoU %, test):

| 모델 | Road-Clear | **Road-Blocked** | Bld No-Dmg | Bld Total-Destr | Tree | mIoU |
|---|---|---|---|---|---|---|
| DeepLabv3+ | 69.7 | 32.9 | 61.6 | 57.2 | 78.6 | 57.43 |
| PSPNet | 98.07 | 94.83 | 95.16 | 98.95 | 99.40 | 95.67 |
| Attention UNet | 98.94 | 98.72 | 99.46 | 99.89 | 99.63 | **98.47** |
| Segmenter (ViT-Tiny) | 87.79 | 51.14 | 65.18 | 89.54 | 97.17 | 68.49 |
| Segmenter (ViT-Small) | 94.63 | 84.10 | 80.74 | 95.85 | 98.58 | 85.78 |

**이 표는 그대로 인용하지 말 것.** 같은 표 안에서 DeepLabv3+ 57.4와 Attention UNet 98.5가 공존하는 것은 학습·평가 조건이 동일하지 않다는 신호다. 같은 연구실의 선행 논문(Chowdhury & Rahnemoonfar, 클래스 8개로 병합한 버전)은 DeepLabv3+ 69.67, PSPNet 80.27, self-attention 약 88 mIoU를 보고한다 `[P, arXiv 2105.14540]`. 즉 90%대 후반 수치는 **재현 가능성이 의심스럽다**고 보고서에 적는 편이 정직하다.

**우리 mIoU 0.6256과 비교 불가 사유**
- 클래스 집합이 완전히 다르다. 우리는 4클래스(normal/fire/collapse/road_blocked), RescueNet은 10클래스. 특히 우리 `collapse`는 RescueNet의 building damage 계열을 통합 매핑한 것이고, `fire`는 RescueNet에 아예 없다.
- 우리 평가 해상도 512, 원 데이터는 3000x4000.
- 우리는 RescueNet 단독이 아니라 화재 세그 데이터와 섞어 학습.
- 우리 road_blocked IoU 0.343은 DeepLabv3+ 32.9와 **우연히 비슷**하지만, 클래스 정의·해상도·split이 달라 같은 의미가 아니다.

## 5. 화재 세그멘테이션 (참고)

우리 fire 클래스의 학습 소스가 어떤 공개 세트인지 이 조사에서는 확정하지 못했다. 항공 화재 세그로 흔히 인용되는 FLAME(Shamsoshoara et al., Computer Networks 2021)의 경우, 원 논문 U-Net 베이스라인이 128x128 입력 500장 축소 조건에서 **IoU 49.75%** `[S]`, 후속 모델들이 70~85% IoU를 보고한다 `[S]`. 우리 fire IoU 0.503과 숫자가 가깝지만, **데이터셋이 같은지 확인되지 않았으므로 보고서에 나란히 놓지 말 것.**

## 6. 여러 데이터셋을 하나의 모델로 함께 학습한 선행 연구

우리와 구조적으로 가장 가까운 비교 대상:

| 연구 | 무엇을 합쳤나 | 보고 수치 | 확인 | 우리와의 차이 |
|---|---|---|---|---|
| **MMPedestron** (Zhang et al., ECCV 2024) | RGB / IR / Depth / LiDAR / Event 를 하나의 encoder로. MMPD 벤치마크(공개 데이터셋 + 자체 EventPed) joint 학습 | LLVIP **AP 72.6** (COCO AP@[.5:.95]), COCO-Persons 71.1. RGB-pretrain만 하면 LLVIP 50.0 → multi-modal joint 학습 시 72.6 | [P, arXiv 2407.10125 표 3] | 사람 검출만 하고 위험구역 세그는 없다. 지표는 AP@[.5:.95](우리 mAP@50이 아님). 항공/재난이 아니라 감시·지상 시점 중심 |
| Detection Hub (Meng et al., CVPR 2023) | COCO / Object365 / Visual Genome 다중 데이터셋 통합 검출 | 단순 concat 대비 +2.3 / +1.0 / +0.9 mAP | [S] | 사람·재난 도메인 아님. "단순 합치기는 taxonomy gap 때문에 성능이 떨어진다"는 근거로만 인용 가치 |
| C2A (UAV 재난 인명 검출 데이터셋, Springer 2024) | 재난 특화 세트 + 일반 사람 세트 결합 학습이 최적이라고 보고 | 구체 수치 미확인 | [S] | 우리 joint 학습 근거로 방향성만 인용 가능 |

**결론: LLVIP + VisDrone + SARD + RescueNet + 화재 세그를 하나의 4채널 백본으로 함께 학습하고, 사람 검출과 위험구역 세그를 동시에 내는 공개 연구는 찾지 못했다.** MMPedestron이 "멀티 데이터셋 joint 학습" 축에서 가장 가깝지만 태스크가 사람 검출 단일이고 도메인이 다르다. 즉 우리 조합에 대한 직접 비교 대상은 **없다**고 보고서에 쓰는 것이 정확하다. 이는 반대로 "공개 베이스라인 대비 우열"을 주장할 근거도 없다는 뜻이다.

## 7. 무엇을 주장할 수 있고 무엇을 주장할 수 없나

주장 가능:
1. 각 데이터셋 공개 수치는 **단일 데이터셋 특화 모델**이 낸 것이고, 우리는 하나의 모델로 5개 소스를 동시에 처리한다. "특화 모델과 같은 자릿수의 성능을 단일 joint 모델로 낸다"는 정도의 정성적 서술은 가능하다(지표가 다르다는 각주 필수).
2. **우리 split 내부의 ablation은 전부 유효하다.** SARD 제외 시 0.4110 → 포함 시 0.8202, v4 → combo에서 VisDrone 0.5104 → 0.6711. 이건 외부 비교가 필요 없다.
3. RescueNet의 road_blocked는 공개 벤치마크에서도 **가장 어려운 클래스**다(DeepLabv3+ 32.9로 최저). 우리 road_blocked 0.343이 다른 클래스보다 낮은 것은 데이터셋 고유의 난이도와 방향이 일치한다 .  정성적 근거로 쓸 수 있다.

주장 불가:
1. 어떤 공개 수치와도 **수치 직접 비교(이겼다/졌다)** 를 할 수 없다. 이유: (a) 점 검출 + 반경 매칭 vs 박스 IoU, (b) split 불일치(VisDrone val 548 vs test 1,580; SARD 자체 394), (c) 클래스 집합 불일치(VisDrone 10클래스 평균 vs person 계열만; RescueNet 10클래스 vs 우리 4클래스), (d) tiled 추론 vs 전체 프레임, (e) 단일 데이터셋 특화 vs joint.
2. SARD 97.15%를 "SOTA"로 인용하며 우리 82.02와 나란히 놓는 것. IoU 정의와 split을 1차 확인하지 못했다.
3. RescueNet 98.47 mIoU를 기준선으로 삼는 것. 같은 표 내부 일관성이 의심스럽다.
4. 화재 세그는 학습 소스 동일성이 확인되지 않아 비교 자체를 시도하면 안 된다.

권장 서술 형식: 표에 공개 수치를 싣되 **"별도 프로토콜, 직접 비교 불가"** 열을 반드시 붙이고, 본문 주장은 우리 내부 ablation에만 근거한다.
