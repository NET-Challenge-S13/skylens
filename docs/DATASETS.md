## 0. 조사 결론 요약

**"RGB+열화상 페어 + 재난현장 + 사람 + 위험구역"이 한 데이터셋에 모두 있는 공개 데이터는 존재하지 않는다.**
따라서 아래 세 축을 **조합**해 헤드별로 나눠 학습하는 것이 현실적이다.

| 축 | 필요한 것 | 대표 데이터셋 |
|---|---|---|
| **A. 4채널(RGB+열) 정합 구조 검증** | RGB·열화상이 시공간 정합된 페어 | **FLAME 3**(항공·화재) · KAIST · LLVIP |
| **B. 위험구역 세그 헤드** (stuff) | 픽셀 단위 마스크 · 재난 · 항공뷰 | **FLAME**(화재 마스크) · **RescueNet**(붕괴 등급) |
| **C. 사람 인스턴스 헤드** | 항공뷰 소형 인물 · 비정상 자세 | **SARD**(RGB) · **AIResQ**(열화상) |

가장 중요한 발견은 **FLAME 3** — 우리가 전제한 "드론이 찍은 RGB+열화상 페어"를 **실제로 그 조건 그대로** 제공하는
유일한 재난 데이터셋이다. (대상이 산불이라 붕괴는 없지만, 4채널 Early Fusion이 성립하는지 검증하는 데는 최적)

## 1. RGB + 열화상 페어 데이터셋 (Early Fusion 검증용)

우리 설계의 **입력단 Early Fusion(RGB 3ch ⊕ 열화상 1ch = 4ch)** 이 성립하려면 두 영상이 **시공간 정합**되어 있어야 한다.
아래 데이터셋들이 그 조건을 만족한다.

| 데이터셋 | 규모 | 시점 | 열화상 | 라벨 | 우리 프로젝트 적합도 |
|---|---|---|---|---|---|
| **[FLAME 3](https://ieee-dataport.org/open-access/flame-3-radiometric-thermal-uav-imagery-wildfire-management)** ⭐ | image quartet 세트 | **UAV(드론) 항공** | ✅ **radiometric**(픽셀당 실제 온도값) | 화재 | ★★★ **최적** — 유일하게 "드론 + RGB/열 페어 + 재난" 3조건 충족 |
| **[KAIST Multispectral](https://soonminhwang.github.io/rgbt-ped-detection/)** | 95,328 페어 | 차량(도로) | ✅ 빔스플리터 정합 | 사람 bbox (103,128) | ★★☆ 규모 최대, 4채널 사람 탐지 사전학습용. 단 **도로 시점** |
| **[LLVIP](https://bupt-ai-cz.github.io/LLVIP/)** | 16,836 페어 | 고정 CCTV | ✅ 정합·크롭 완료 | 사람 bbox | ★★☆ **전부 야간** — 야간 재난 대응 시나리오와 부합 |

### FLAME 3가 특별한 이유

- **image quartet 구조**: `raw RGB` + `raw thermal` + `FOV 보정된 RGB` + `thermal TIFF` 4장 세트 → FOV 보정본이 있어 **4채널 concat을 바로 할 수 있음** (별도 정합 작업 불필요)
- **radiometric thermal**: 컬러팔레트로 렌더된 가짜 열화상이 아니라 **픽셀당 실제 온도값**. 연기에 가려 불꽃이 안 보여도 온도로는 hotspot이 잡힘 → ARCHITECTURE.md에서 "가시광이 약한 야간·연기 상황을 열화상이 보완한다"고 쓴 근거를 **실측 데이터로 증명**할 수 있음
- **NADIR Thermal Fire set**: 3~5초 간격 지오레퍼런싱된 상공 열화상 시계열 → 드론 재방문/시계열 시나리오와 구조가 유사

> ⚠️ IEEE DataPort 계정 필요(무료). 대상이 **산불**이라 건물 붕괴는 없음 → 붕괴는 §2의 RescueNet으로 보완.

## 2. 위험구역(stuff) 세그멘테이션 데이터셋

세그 헤드는 **픽셀 단위 마스크**가 필요하다. 분류(classification)만 있는 데이터셋은 이 헤드 학습에 직접 못 쓴다.

| 데이터셋 | 규모 | 라벨 형식 | 클래스 | 적합도 |
|---|---|---|---|---|
| **[RescueNet](https://github.com/BinaLab/RescueNet-A-High-Resolution-Post-Disaster-UAV-Dataset-for-Semantic-Segmentation)** ⭐ | 4,494장 | ✅ **픽셀 시맨틱 마스크** | 건물 무손상/경미/심각/**전파**, 도로 정상/**차단**, 물, 차량, 나무, 수영장 (11종) | ★★★ **붕괴 위험구역에 최적** — 손상 **등급별** 마스크 + 도로 차단 여부까지 (허리케인 Michael, UAV 촬영) |
| **[FLAME](https://ieee-dataport.org/open-access/flame-dataset-aerial-imagery-pile-burn-detection-using-drones-uavs)** | 2,003 마스크 (+분류 39,375장) | ✅ 픽셀 마스크 | 화재 | ★★★ **화재 위험구역용** · 드론 촬영 + 열화상 히트맵 동봉 |
| **[FSSD](https://www.mdpi.com/2079-9292/12/18/3778)** | — | ✅ 시맨틱 마스크 | 화염 + **연기** 분리 | ★★☆ 실내 화재 · 연기를 별도 클래스로 다룸 |
| **[AIDER](https://github.com/ckyrkou/AIDER)** / AIDERv2 | 8,540 / 16,723장 | ❌ **분류 라벨만** | 화재·홍수·**붕괴건물/잔해**·교통사고·정상 | ★☆☆ 세그 헤드엔 직접 못 씀. 웹 수집 이미지라 화질·시점 편차 큼. **사전학습 백본 워밍업**용 |
| **[xBD](https://xview2.org/)** | 대규모 | ✅ 건물 폴리곤 + 손상등급 | 19종 재난 | ★☆☆ **위성** 시점 — 드론 저고도 시점과 스케일 갭 큼 |

> **RescueNet의 "Road-Blocked"** 클래스는 지휘관 관점에서 특히 가치가 큼 —
> IDEA.md의 홍제동 사례(진입 경로 판단)와 직결되는 정보라 데모 서사로 쓰기 좋다.

## 3. 사람(인스턴스) 데이터셋

우리 시나리오의 사람은 **항공뷰 · 소형 · 비정상 자세(쓰러짐)** 라는 점에서 일반 보행자 데이터셋과 다르다.

| 데이터셋 | 규모 | 모달리티 | 특징 | 적합도 |
|---|---|---|---|---|
| **[SARD](https://www.researchgate.net/figure/Examples-of-human-detection-on-the-SARD-dataset_fig1_362085875)** ⭐ | 1,980장 / 6,525 인스턴스 | RGB | **UAV 촬영 SAR 전용**. 서기·앉기·걷기·달리기 + **탈진/부상자 자세**. 중앙값 면적이 전체의 **0.1% 미만**(초소형 객체) | ★★★ 우리 시나리오와 **자세·시점·스케일이 정확히 일치** |
| **[AIResQ](https://www.nature.com/articles/s41597-026-07663-9)** ⭐ | 9,788장 | **열화상**(최대 2048×1536) | 드론 시점 SAR, 다양한 날씨·지형, **사고 상황 비정상 자세** | ★★★ **고해상도 열화상** — 차세대 드론 IR 카메라 대비. 열화상 단독 채널 학습에 최적 |
| KAIST / LLVIP | §1 참조 | RGB+열 페어 | 도로/CCTV 보행자 | ★★☆ 4채널 구조 검증용(도메인 갭 있음) |

> **SARD의 "중앙값 면적 < 0.1%"** 는 중요한 신호다 — 드론 고도에서 사람은 수십 픽셀에 불과하므로,
> UNet 인스턴스 헤드 설계 시 **고해상도 입력 유지 + 얕은 층 스킵 커넥션 활용**이 필수다.
> (이 점은 ARCHITECTURE.md §3-A에서 사람을 "잔해 속 소형 객체"라고 규정한 것과 일치)

## 5. 권장 학습 전략

### 전략 A — 헤드별 분리 학습 (권장)

두 헤드가 요구하는 데이터가 완전히 다르므로, **공유 백본 + 헤드별 데이터셋**으로 나눠 학습한다.
(ARCHITECTURE.md §3-A의 "단일 백본 · 이중 헤드" 구조를 그대로 활용 — 백본은 두 데이터 모두로 학습됨)

```
1단계  백본 사전학습
       └─ KAIST(95K) 또는 LLVIP(16K)로 4채널 입력 처리 능력 확보
          → "RGB+열 concat이 실제로 학습되는가"를 최대 규모 데이터로 먼저 검증

2단계  세그 헤드 (위험구역)
       ├─ FLAME(2,003 마스크)      → 화재 위험구역
       └─ RescueNet(4,494 마스크)  → 붕괴 위험구역 + 도로 차단
          ※ 클래스 체계를 {정상 / 화재 / 붕괴 / 차단} 으로 통합 매핑 필요

3단계  인스턴스 헤드 (사람)
       ├─ SARD(6,525 인스턴스)  → 항공뷰 소형·비정상 자세 (RGB)
       └─ AIResQ(9,788장)       → 열화상 채널 (야간·연기 대응)

4단계  4채널 통합 검증
       └─ FLAME 3 (RGB+radiometric thermal 페어, 드론 항공)
          → 실제 운용 조건에 가장 가까운 데이터로 최종 검증
```

### 전략 B — 중간평가 최소 경로 (시간 부족 시)

PROJECT.md §7이 "탐지는 수동 좌표 트리거여도 무방"하다고 정해둔 만큼, 최소한으로는:

- **SARD + RescueNet(RGB 3채널만)** 으로 학습 → "AI가 실제로 탐지한 결과"라고 말할 수 있는 최소 조건 충족
- 열화상 4채널은 **"KAIST/LLVIP로 구조 검증 완료, 최종평가에서 FLAME 3 기반 확장"** 으로 로드맵 발표

이 경우에도 PROJECT.md §7의 원칙(연출과 실제의 경계를 숨기지 않는다)을 지켜 발표하는 것이 신뢰도에 유리하다.

## 6. 알려진 갭과 대응

| 갭 | 영향 | 대응 |
|---|---|---|
| RGB+열 페어 + **붕괴** 데이터 없음 | 붕괴 위험구역을 4채널로 학습 불가 | 붕괴는 RGB(RescueNet)로, 4채널 검증은 화재(FLAME 3)로 분리 |
| 데이터셋별 **시점 불일치** (위성/차량/CCTV/UAV) | 도메인 갭으로 성능 저하 | UAV 촬영본(FLAME·FLAME 3·RescueNet·SARD·AIResQ) **우선 사용** |
| 사람이 **초소형 객체** (<0.1% 면적) | 다운샘플링 시 소실 | 고해상도 입력 + 얕은 스킵 커넥션 · 타일 단위 추론 검토 |
| 클래스 체계 제각각 | 통합 학습 불가 | {정상/화재/붕괴/차단} 공통 스키마로 **사전 매핑 작업 필요** |
| 재난+사람이 **동시에** 있는 데이터 없음 | 이중 헤드 동시 학습 어려움 | 헤드별 분리 학습(전략 A) — 배치마다 해당 헤드만 loss 계산 |
